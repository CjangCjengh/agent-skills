# 演示视频与去 AI 味

- 先确定观众要从视频里看到什么行为及结果，再决定需要哪些文字和面板。自动操作、语音指挥、聊天陪伴是不同的展示目标；沿用当前项目已经确认的目标，不把其他项目的设定带进来。

- 从现有对话和素材中提取已经确认的受众、素材来源、声音、画面形式和演示范围，不让用户重复说明。无配音、左右分栏、自己录制等要求按项目执行，不推广成所有视频的固定模板。

- 用户要一段 demo 时，把工作限制在足以录出目标行为的场景。允许固定路线、预设触发、脚本回放或后台控制时，可以采用这些办法；不自行扩大成训练通用模型、完成整款游戏适配或建设生产服务。也不以建议、分镜或静态页面代替用户要求的成片。

- 素材来源按用户要求处理。要求自行录制时，从实际运行的游戏或软件采集画面，外部视频只能用作参考，不拿来拼接、换皮或冒充自己的运行结果。使用可控场景可以简化制作，但画面里仍应有实际的操作过程。

- 片内文字写具体对象、动作和结果，不用“重新定义陪伴”“让智能真正走进世界”等宣言代替演示。删掉无来由的感慨、煽情、排比和自我赞美，也不要替观众宣布“这就是 AI 的力量”。能从画面直接看出的事情通常无需再标一遍。

- 按受众使用自然的语言。面向中文受众时，说明文字优先用中文；代码、函数名、模型名和常见界面词可以保留英文，不强行翻译 Thinking、token 等当前场景里清楚的叫法，也不加装饰性的英文副标题。普通文案少用斜杠堆并列词，代码、路径和原有界面中的必要符号保留。

- 画面以实际操作为主，附加内容只保留帮助理解当前过程的部分。需要同时展示运行过程时，可以采用游戏或软件画面加一个过程栏；比例按可读性调整，不为了左右对称把主体缩得看不清。没有必要时就保留完整录屏。

- 去掉模板自动添加的页眉、页脚、编号、制作版本、徽章和说明性小字。不要每个区域都加标题、副标题、边框和一句解释。正常的游戏 HUD、工具输出和必要状态信息可以保留；去掉装饰不等于清空有用信息。

- 参考 Codex、Claude Code 等 harness 风格时，借用正常工作界面的组织方式：用户指令、当前状态、工具调用、结果、必要的脚本修改。用清楚的层级和适量留白，不靠满屏卡片、发光边框、随机滚动代码或密集数字制造技术感。

- 过程栏的每条内容都应对应正在发生的事。Thinking 可以是简短的任务判断，例如“门口有敌人，先退到墙后”；调用时展示实际输入和返回，失败或改计划时才出现相应变化。不机械循环“观察、分析、决策、执行”，不为了显得繁忙持续刷无关日志，也不声称简短状态摘要是模型完整的内部思考。

- 展示视觉调用时，输入应来自同一段录屏的当前帧、连续帧或有必要的局部裁切，返回结果与画面中的对象、位置和状态对应。观众应看得出模型收到了什么、输出了什么、接下来执行什么。只有实际使用了检测框、分数或延迟数据时才展示这些数值，不随手编一组精确小数装饰面板。

- 展示代码时，选取这次演示实际使用且与当前行为有关的脚本、参数或修改片段；接口名称和返回格式以实际实现为准。不要把伪代码、未接通的 API 或无关源码排成一个正在执行的程序。只需展示能解释当前变化的部分，不为了填满右栏塞入整份代码。

- 编排演示时，保持指令、画面、调用和结果之间的因果关系。后台用脚本执行，就可以展示脚本的实际调用记录；用户授权流程重演时，预设请求和响应也要对应同一段素材，不必为展示补做完整推理系统。制作记录中区分实际运行与预设部分，不能把重演描述成已验证的模型能力；需要对外说明演示性质时，用简短、适当位置的说明，不自动给每个画面堆提示小字。

- 如果演示采用大模型规划、轻量模型实时控制的方案，就按这个频率差呈现：大模型在任务开始、异常或策略转向时判断并调整脚本，视觉和动作层持续更新。不要把每一帧动作都写成长篇大模型推理，也不要把低频规划日志伪装成逐帧控制。这只是相关项目的展示方式，不默认替用户指定架构。

- 若轻量 LLM 或 MLLM 只解码一个 token 做动作选择，应让画面中的候选动作、输出 token 与执行动作对应，动作名称或映射足够清楚即可。脚本修改要影响后面的实际行为，例如改变撤退条件或行走目标，避免右边反复“修改策略”、左边始终播放同一段动作。

- 连贯性检查同时覆盖两边。地图、位置、朝向、装备、血量、弹药、敌人状态及任务进度都要承接前一镜；过程栏不能把几段互不相干的录像包装成一次连续执行。需要换场时，在自然的任务边界切换，并同步切换右栏状态。

- 围绕动作安排时间：指令和输入先出现，执行随后发生，结果在完成后返回。可以剪短等待，但两边应同步压缩；长输出留出阅读时间，不强求所有日志完整展开，也不让结果先于动作出现。重复路线和空转画面不能靠加快日志掩盖。

- 展示操作能力要有可见的判断和反馈。游戏战斗可以选择有目的的走位、寻找掩体、及时躲避、抓住空档攻击等过程，保留对手的反应。站着互相掉血、对空开枪或长时间不行动，不能靠字幕改写成高水平操作；用可控且有来回交互的场景重录，不必强求无伤碾压。

- 用户要求清理测试昵称、版本串或调试标记时，先检查显示配置、HUD 组件或源码中的渲染位置，从来源关闭并重新录制。裁剪、遮挡作为无法处理来源时的备选，不能顺手裁掉准星、血条、道具栏等必要画面。是否属于正常游戏界面应先核实，不能仅凭字小就判断该删。

- 不默认添加旁白、合成播音、配乐或口号。用户要求无配音时保留合适的原始声音；若另有语音指挥需求，用户的指令属于输入，不应和旁白一起删掉。声音、字幕与实际指令和执行时刻对应，不用解说掩盖操作断裂。

- 修改以最新确认稿为基准。用户指出一类问题时检查全片同类内容，例如所有角落的测试标记、所有装饰性英文、所有跳接点；同时保留已确认的画面和措辞，不借局部修改重做其他部分。

- 交付前观看实际导出的当前版本，检查开头、切换、动作完成及结尾，并回看被修改的片段。静态截图和生成脚本正常不代表视频连贯；确认旧标记没有残留、代码和文字可读、过程栏没有漂移、声音与画面同步。交付当前文件，简短说明已改内容及尚未解决的具体问题，不用长篇自查报告代替成片。
